# Спецификация: правки по ревью

Критерии приёмки для доработок по замечаниям ревьюера. Подробный план с потоками данных ведётся отдельно;
требования к продукту обновляются в `capabilities.md`, контракт в `contracts/`.

| № | Замечание | Критерий приёмки |
| --- | --- | --- |
| 1 | `COPY app` слишком рано в Dockerfile | После правки `backend/app/*` слой установки зависимостей остаётся `CACHED` |
| 2 | Не фиксируются версии пакетов | Образ ставит зависимости с `--require-hashes`; `make lock-check` зелёный; образы и pip-пакеты deploy заданы точными версиями |
| 3 | CD без CI | PR запускает `make check`; красный CI останавливает deploy, в том числе `workflow_dispatch`; `make check` работает на чистом клоне |
| 4 | Нет фоновой работы | Сервис `worker` есть в обоих compose; задание переживает перезапуск; после 8 ошибок становится `failed` |
| 5 | Проблемы из `backend-plan.md` | Вопрос о тройках закрыт, разделы про фон, алгоритм и M-02 обновлены |
| 6 | Подбор только в запросе пользователя | Правка времени рейса пересчитывает трансферы без участия пользователя; повторный запуск ничего не меняет |
| 7 | Подбор сразу создаёт пару | Третий совместимый попадает в пару, `PUT` отвечает `assigned`; если кто-то уехал, дополнения нет |
| 8 | Нет телеметрии | Лог в JSON с `request_id`; метрики есть; `/metrics` недоступен через nginx; тест на отсутствие телефона в логах |
| 9 | Нет истории изменений | На каждый выход есть запись кто, когда, почему; история восстанавливает текущие составы; UPDATE и DELETE запрещены |

## Границы

- Контракт `PUT /my-application` не меняется.
- Телеметрия только в коде, внешнего хранилища нет.
- Экран истории на фронте делается отдельно.
- Исключение при правке рейса происходит только при нарушении правил совместимости (допущение до ответа заказчика).
