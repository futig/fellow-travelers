# Фронтенд pre-MVP: экраны, переходы, инкременты

Требования — [`Capabilities_Poputchiki.md`](Capabilities_Poputchiki.md) (колонка pre-MVP), API — [`contracts/`](contracts/)
(`openapi.yaml` — источник истины, типы — `frontend/src/api/schema.d.ts`), макеты — Figma
«Поиск попутчика» (`fbiy0nqnjZQ1gpYOIeNgep`, страница «Макеты»). Здесь — как макеты ложатся на pre-MVP и бэкенд.

## Что берём из макетов и что меняем

| Макет | В pre-MVP |
| --- | --- |
| 1. Ваши данные (шаг 1 из 5) | Как есть (уже сделан). «Изменить фото» не делаем — фото из Telegram. |
| 2. Рейс: город вылета → список рейсов; «Найти по номеру» → номер + дата → «Это ваш рейс?» | Поставщика нет: всё строится по `GET /events/{id}/trips` (рейсы, которые ввёл админ). Города — уникальные `departure_location.city`. Поиск по номеру и дате — фильтр того же списка. Логотипов и названия авиакомпании нет в контракте — показываем только номер (`SU1148` → `SU 1148`). |
| 3. Летите с кем-то? | «Один» → `with_companion=false`; «+1» → `true`; «Не искать попутчиков» → `seek_companions=false` (заявка сразу `solo`). |
| 4. Багаж | «Только ручная кладь» → 0; «С багажом» → счётчик 1..2 (больше 2 нельзя — подсказка «Больше двух мест не поместится в одно такси — выберите „Не искать попутчиков“»). |
| 5. Ожидание | «Не хочу ждать» 0, «15 минут», «30 минут». «Другое время» **не делаем** (`WaitMinutes` = 0/15/30). |
| 6. Всё верно? | Сводка с ✏️ на каждом пункте → возврат к шагу. «Да, всё верно» → `PUT my-application`. |
| 7. До вылета (с попутчиками / не нашлись / еду один / задержка) | Экран «Моя поездка» по `GET /events/{id}/my-trip`. «Карта» не показываем (MVP, нет координат). «Общий чат» — только если `event.chat_url`. Задержка: если `estimated_arrival` ≠ `scheduled_arrival` — красное время + зачёркнутое плановое. |
| 7.c Отменить поиск? | Подтверждение для «Поеду один» (`go-solo`). Тот же паттерн — для «Отменить участие» и «Уехал». |
| 8. Прилёт («Я вышел из самолёта», «Я получил багаж») | Таких отметок нет в бэкенде — **не делаем**. После прилёта сразу шаг «Я на месте». |
| 9–10. Путь к месту встречи / На месте | «Я на месте» → `PUT marks {at_meeting_point:true}`. Статусы попутчиков: «На месте» / «Идёт к месту встречи». |
| 11. Заказ такси | Яндекс Go — MVP (`taxi.yandex_go_url = null`): показываем адрес посадки и назначения с кнопкой «Скопировать». Если URL не null — тёмная кнопка «🚕 Заказать такси». Отдельная кнопка «Я уехал» → подтверждение → `PUT marks {departed:true}` (необратимо). |
| Табло администратора | Табло рейсов — MVP. В pre-MVP: управление группой с вкладками «Участники» / «Трансферы» (стиль вкладок — из «Группы трансферов»), карточка трансфера — из «Трансфер — детали». |
| Страница ошибки | 👀 + «Не удалось загрузить страницу» + текст + «Повторить попытку →». |

Экранов в макетах нет — делаем в том же визуальном языке (Header уровня 1, белые карточки-опции, кнопки 54px):
«Мои группы», ввод кода, превью приглашения, создание/настройки группы, приглашение (код + ссылка),
рейсы группы (админ), форма рейса.

## Навигация

Memory router (`createMemoryRouter`), BackButton Telegram — `useBackButton`. Старт по `start_param`
(`contracts/README.md` §6):

| start_param | Первый экран |
| --- | --- |
| `join_<CODE>` | Превью приглашения |
| `event_<uuid>` | Моя поездка |
| `admin_<uuid>` | Управление группой |
| `admin` | Мои группы с фильтром «Управляю» |
| нет | Мои группы |

Маршруты (ориентир):

```
/                         Мои группы (EventSummary: участвую / управляю)
/join                     Ввод кода
/invite/:code             Превью приглашения → «Вступить» → /events/:id
/events/new               Создание группы → /events/:id/admin
/events/:id               Моя поездка (если заявки нет — кнопка «Заполнить заявку»; админ без участия — предложение вступить)
/events/:id/apply/:step   Мастер заявки: profile → flight (city|number|list|confirm) → companion → baggage → wait → review
/events/:id/admin         Управление: вкладки «Участники» / «Трансферы», ссылки на рейсы, настройки, приглашение
/events/:id/admin/settings  Настройки (PATCH, в т.ч. «Закрыть вступление»)
/events/:id/admin/invite  Код и ссылка, «Поделиться» (t.me/share/url), «Скопировать»
/events/:id/admin/trips   Рейсы группы, добавить / изменить / удалить (TRIP_IN_USE → объяснение)
/events/:id/admin/transfers/:tid  Состав трансфера
```

Переключение «моя поездка ↔ управление» — для админа, который ещё и участник: ссылка в шапке экрана.

## Поведение, завязанное на бэкенд

- Без телефона (`has_phone=false`) заявку не отправить: шаг 1 мастера блокирует «Далее»; на `403 PHONE_REQUIRED` — вернуть на шаг 1.
- Админ без участия: на «Моя поездка» — «Вы управляете группой. Если едете сами — вступите как участник» → `POST /invites/{code}/join` (код из `GET /events/{id}/invite`).
- `PUT` при `assigned` → `409 APPLICATION_LOCKED`. Поэтому «Изменить данные» при `assigned` — подтверждение
  «Вы выйдете из текущей группы попутчиков, после изменения поищем заново» → `go-solo` → мастер с данными
  заявки → `PUT` с `seek_companions: true`. Из мастера всегда отправляем `seek_companions` явно.
- `solo` → «Найти попутчиков» (`resume-search`); `cancelled` → «Вернуться в поиск» (`resume-search`).
- После «Уехал» (`departed_at != null`) — никаких действий, только «Хорошей дороги».
- Ответ мутации — актуальная `Application`; после любой мутации инвалидируем `my-trip`, `my-application`, `me/events`.
- Обновление: при открытии экрана, кнопкой «Обновить» в пустых состояниях и при возврате фокуса окна
  (`refetchOnWindowFocus`). Push нет.
- Ошибки: `message` показываем как есть; `422` — `details.fields` под полями формы; `404` — «Группа не найдена»;
  `401`/нет initData — `OpenInTelegramScreen`.

## Время

- Время рейса показываем **в часовом поясе своего аэропорта**: вылет — `departure_location.timezone`, прилёт — `arrival_location.timezone` (`Intl.DateTimeFormat` с `timeZone`). Не в часовом поясе устройства.
- Прилёт на следующие сутки относительно вылета — пометка `+1`.
- Дата рейса — «22 августа» (дата вылета в его поясе).
- Заголовок «Моя поездка»: до `scheduled_departure` — «До вылета N дней / часов / минут» (правильные падежи);
  между вылетом и `effective_arrival` — «В пути, прилёт в 12:25»; после — «Добро пожаловать в {arrival city}».
- Отметки «Я на месте» / «Уехал» доступны с `effective_arrival − 60 мин`.
- Админ вводит время рейса **локальным временем аэропорта без смещения** (`2026-08-22T08:40:00`) — бэкенд сам применит пояс аэропорта.

## Инкременты

Каждый инкремент — своя ветка `feature/frontend-pre-mvp-step-N` от `feature/frontend-pre-mvp`, после ревью и аудита
вливается в неё. В `main` вливает пользователь.

0. Контракт `seek_companions` + бэкенд.
1. **Фундамент**: токены, Martian Mono, UI-кит (Option, FlightOption, FlightInfo, FellowList, NumberInput, EmptyState,
   Tabs, SectionHeader, варианты Button, ConfirmScreen), новая страница ошибки, утилиты времени, API-слой
   (функции + query keys + хуки TanStack Query для всех pre-MVP эндпоинтов), маршрутизация по `start_param`.
2. **Мои группы и вступление**: «Мои группы», ввод кода, превью приглашения, вступление.
3. **Админ: группа и рейсы**: создание и настройки группы, приглашение, рейсы группы (CRUD, поиск аэропортов).
4. **Мастер заявки**: шаги 1–5 + «Всё верно?», отправка, ошибки.
5. **Моя поездка**: все состояния (до вылета / в пути / после прилёта; searching / assigned / solo / cancelled / уехал),
   действия, отметки, такси, подтверждения.
6. **Управление: участники и трансферы**: счётчики, фильтры, список участников, трансферы, состав трансфера.

## Статус (на 2026-10-18, ветка `feature/frontend-pre-mvp`)

Инкременты 0–6 готовы, прошли ревью и влиты; финальный аудит безопасности проведён, его medium-находка закрыта
шагом 7 (`chat_url` — только ссылки на чат Telegram, схема `ChatUrl` в контракте, проверка на бэкенде и фронте).
Фронт: 428 тестов; бэкенд: 546 тестов.

Отложенные minor-замечания ревью (по решению — не дорабатывали):
- Настройки группы: «Закрыть вступление» сбрасывает несохранённые правки формы.
- Форма рейса: одинаковая иконка у аэропорта вылета и прилёта; тест удаления не моделирует обновлённый список.
- Хаб: после «Вступить как участник» «Назад» из поездки возвращает в хаб.
- Мастер: при `PHONE_REQUIRED` не инвалидируется `me`; «Не искать попутчиков» сбрасывает «+1»; отступы формы поиска по номеру.
- Моя поездка: выход из мастера после «Изменить данные» (go-solo) оставляет заявку `solo` без подсказки;
  «Летит тем же рейсом» — по номеру без даты; ссылка «Управление группой» выше карточки рейса.
- Трансфер: «‹ Все трансферы» ведёт назад по истории (может вернуть на «Участники»); вкладки ниже меню хаба;
  статус «Такси заказано» из макета не реализован (нет данных в pre-MVP).

Остаточные риски из аудита: `yandex_go_url` проверяется только на `https:` (сузить до хостов Яндекс Go в MVP);
CSP `img-src https:` (сузить, когда станут известны домены фото); `X-Forwarded-*` в nginx доверяются клиенту
(зафиксировать TLS-терминатор перед nginx); видимость контактов обеспечивает только бэкенд.
